# Sync entre máquinas pela LAN — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sincronizar lembretes, Ajustes (allowlist) e histórico de mensagens com mídia entre os Macs do usuário, pela LAN, num canal autenticado — sem servidor central.

**Architecture:** Um serviço Bonjour novo (`_knobler-sync._tcp`) com TLS-PSK obrigatório carrega um `SyncPacket` próprio, emoldurado pelo `Frame` que as mensagens já usam (generalizado pra qualquer `Codable`). A reconciliação é um LWW-Element-Set com relógio híbrido (HLC) e tombstones, em funções puras testáveis fora do app. O `Packet` das mensagens **não é tocado**.

**Tech Stack:** Swift 5, SwiftUI + AppKit, macOS 14.2 como deployment target. Projeto gerado por XcodeGen. Testes são binários `tools/*check.swift` com `assert`, rodados por `tools/check.sh` — **não existe XCTest neste repo**.

**Spec:** `docs/superpowers/specs/2026-07-29-sync-lan-design.md`. Viabilidade: `docs/superpowers/specs/2026-07-29-sync-lan-research.md`.

### Task 1: HLC e merge, puros

**Files:**
- Create: `Knobler/SyncClock.swift`, `Knobler/SyncMerge.swift`
- Create: `tools/synccheck.swift`
- Modify: `tools/check.sh`

**Interfaces:**
- Produces: `struct HLC: Codable, Comparable` (`wall: Int64`, `counter: UInt32`, `node: String`), `func tick(now:) -> HLC`, `func observe(_ remoto: HLC, now:) -> HLC`
- Produces: `protocol SyncItem { var syncID: String { get }; var hlc: HLC { get }; var apagado: Bool { get } }`, `func merge<T: SyncItem>(_ local: [T], _ remoto: [T]) -> [T]`

**Steps:**
- [ ] `HLC` com a regra padrão: se o relógio de parede avançou além do maior visto, usa ele e zera o contador; senão mantém e incrementa o contador. `node` desempata.
- [ ] `merge` por `syncID`, vencendo o maior `hlc`; tombstone (`apagado: true`) vence empate de conteúdo e **nunca** é descartado pelo lado que não conhece o item.
- [ ] `tools/synccheck.swift`: relógio atrasado não vence; convergência é a mesma nas duas ordens de aplicação (`merge(a,b) == merge(b,a)`); tombstone não ressuscita depois de dois merges; dois nós com o mesmo `wall`/`counter` convergem pro mesmo vencedor.
- [ ] Entrada nova em `tools/check.sh`.

**Verification:** `./tools/check.sh` passa com o check novo.

### Task 2: PSK no Keychain e base32

**Files:**
- Create: `Knobler/SyncKeychainStore.swift`, `tools/synckeychaincheck.swift`
- Modify: `tools/check.sh`

**Interfaces:**
- Produces: `enum SyncPairingState { case unpaired, ready(Data), locked }`, `static func pairingState() -> SyncPairingState`, `save/clear`, `base32(_:)`/`fromBase32(_:)`

**Steps:**
- [ ] Gerar com `SymmetricKey(size: .bits256)`; nunca logar a chave nem colocá-la em `UserDefaults`.
- [ ] Distinguir "nunca pareado" de "pareado mas trancado" — exatamente o caso de ACL que o `WebhookKeychainStore` já trata (ver pesquisa R3).
- [ ] Base32 sem caracteres ambíguos, com roundtrip coberto por `assert`.
- [ ] Entrada nova em `tools/check.sh`.

**Verification:** `./tools/check.sh`; os três estados cobertos sem tocar o Keychain real.

### Task 3: canal autenticado

**Files:**
- Create: `Knobler/SyncPacket.swift`, `Knobler/SyncService.swift`
- Modify: `Knobler/Wire.swift`, `Knobler/Info.plist`, `project.yml` (arquivos novos → `xcodegen generate`)

**Interfaces:**
- Produces: `SyncService.start()/stop()`, `@Published var parPareado: Bool`, `@Published var ultimoEncontro: Date?`
- Consumes: `SyncKeychainStore`, `Frame`

**Steps:**
- [ ] `NWParameters` com `sec_protocol_options_add_pre_shared_key` e `min = max = .TLSv12`. **Não** pedir TLS 1.3: o handshake falha com `-9858` (pesquisa R1). Fixar o `max` de propósito, pra um macOS futuro que suba o piso não quebrar em silêncio.
- [ ] `Frame` generalizado pra `Codable`; `wirecheck` continua verde sem mudança de comportamento.
- [ ] Listener e browser do `_knobler-sync._tcp`, com a entrada no `Info.plist`.
- [ ] `SyncPacket` com campo `v`; versão desconhecida é recusada com log, sem derrubar o par.
- [ ] Dois listeners no mesmo processo (mensagens + sync) — **não testado na pesquisa**, verificar ao vivo que o `_knobler._tcp` continua sendo descoberto.

**Verification:** dois Macs (ou duas cópias com PSK igual) fecham handshake; PSK errado é rejeitado; mensagens LAN continuam funcionando com um Mac não pareado.

### Task 5: mídia em duas fases

**Files:**
- Modify: `Knobler/SyncService.swift`, `Knobler/SyncPacket.swift`

**Steps:**
- [ ] Fase 1: manifesto (texto + quais mídias existem, por nome de arquivo).
- [ ] Fase 2: um frame por mídia faltante — cada anexo é ≤ 6 MB e o frame aceita 12 MB, então **sem chunking**; o que já chegou não é pedido de novo (retomada de graça).
- [ ] Mídia recebida passa por `MediaKind.validate` antes de gravar, igual à das mensagens.
- [ ] Referência ausente degrada pra "imagem não disponível nesta máquina" — estado que o `MessageStore` já produz ao podar.
- [ ] Medir o tempo de reconciliação com histórico cheio (pendência da pesquisa) e decidir se precisa progresso no card.

**Verification:** foto enviada num Mac aparece no outro; interromper no meio e reconectar não re-baixa o que já chegou.
