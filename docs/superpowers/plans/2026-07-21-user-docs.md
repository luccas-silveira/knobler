# Documentação Completa de Usuário — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Documentar, do ponto de vista do usuário final, todas as ~16 funcionalidades do Knobler em `docs/*.md`, com screenshot real de cada uma — estendendo o harness `tools/main.swift` pra cobrir as telas que hoje não têm snapshot (Messages, painéis de Ajustes, editor de mapeamento de webhook).

**Architecture:** O harness de snapshot (`tools/main.swift`, técnica `ImageRenderer` offscreen) já cobre os estados dentro do notch. Vamos (1) adicionar hooks `injectPreview` a `WebhookClient` e `LANMessaging` pra evitar chamadas de rede reais durante o render, (2) adicionar cenários novos ao loop existente pra Mensagens, (3) adicionar uma função de render dedicada pra `SettingsView` (8 painéis) e outra pra `MappingEditorView` — ambas seguindo o padrão já existente de `renderOverlay` (usado hoje só pro Descanso). Depois disso, cada feature ganha um `docs/<slug>.md` com um template fixo (O que faz / Como usar / Permissões) e o(s) screenshot(s) embutido(s). Por fim o `README.md` ganha bullets para as features que hoje não aparecem nele (Dictation, Ask, Pomodoro, Descanso, Reminders, Shelf, Messages, Webhooks, AirPods, Mirror) e um link de cada bullet pro doc correspondente.

**Tech Stack:** Swift 5 / SwiftUI / AppKit (`ImageRenderer`), `swiftc` direto (sem Xcode) via `tools/snapshot.sh`, Markdown.

## Global Constraints

- Todo texto de doc e commit é em **pt-BR** (convenção do projeto, ver `CLAUDE.md`).
- Nenhum novo screenshot pode disparar rede real, EventKit, Bluetooth ou câmera reais — só dados fake injetados (ver hooks `injectPreview` abaixo). Exceção documentada: a feature **Mirror** não ganha screenshot automático (ligaria a câmera de verdade dentro do script de build) — só texto.
- Template fixo de cada `docs/<slug>.md`:
  ```markdown
  # <Título>

  ![<alt>](../Snapshots/<arquivo>.png)

  ## O que faz

  <2–4 frases>

  ## Como usar

  <bullets: gesto/atalho/comando/onde configurar>

  ## Permissões

  <permissão + string exata do Info.plist, ou "Nenhuma permissão especial.">
  ```
  Para docs com mais de um screenshot, repita a linha `![alt](../Snapshots/arquivo.png)` com legenda em itálico abaixo de cada uma, todas dentro de "O que faz".
- Convenção de nome dos hooks de harness: `injectPreview(...)`, mesmo nome/padrão já usado em `Knobler/MediaController.swift:51`.
- `tools/snapshot.sh` já compila todos os arquivos Swift necessários (`SettingsView`, `WebhookSettingsView`, `MappingEditorView`, `RemindersView`, `IdentitySettingsView`, `MessagesView`, `IncomingMessageView`, `LANMessaging`, etc. já estão na lista) — nenhuma mudança nesse arquivo é necessária, só em `tools/main.swift`.

```swift
// Cenários de Mensagens LAN — precisam de LANMessaging/MessageStore no
// ambiente, que os demais cenários não usam.
@MainActor func renderMessageScenario(
    _ name: String, realNotch: Bool,
    configure: (NotchViewModel, LANMessaging, MessageStore) -> Void
) {
    let vm = NotchViewModel()
    let media = MediaController()
    media.injectPreview(state: nil, artwork: nil)
    let lan = LANMessaging()
    let store = MessageStore()
    vm.hasRealNotch = realNotch
    vm.notchSize = realNotch
        ? CGSize(width: 200, height: 32)
        : CGSize(width: 190, height: 30)
    configure(vm, lan, store)

    let view = ZStack(alignment: .top) {
        LinearGradient(
            colors: [Color(red: 0.72, green: 0.78, blue: 0.88),
                     Color(red: 0.90, green: 0.86, blue: 0.80)],
            startPoint: .topLeading, endPoint: .bottomTrailing
        )
        NotchView(vm: vm, media: media, levels: SystemAudioLevels(),
                  shelf: currentShelf, dropTargetsEnabled: false)
            .environmentObject(lan)
            .environmentObject(store)
    }
    .frame(width: 560, height: 240)

    let renderer = ImageRenderer(content: view)
    renderer.scale = 2
    guard let nsImage = renderer.nsImage,
          let tiff = nsImage.tiffRepresentation,
          let rep = NSBitmapImageRep(data: tiff),
          let png = rep.representation(using: .png, properties: [:])
    else { print("FALHOU: \(name)"); exit(1) }
    let path = "\(outputDir)/\(name).png"
    try? png.write(to: URL(fileURLWithPath: path))
    print("ok \(path)")
}
```

```markdown
# Now Playing

![Notch fechado com música tocando](../Snapshots/closed-music.png)

*Fechado — capa + visualizador.*

![Notch expandido em música](../Snapshots/music-expanded.png)

*Aberto (hover) — controles, progresso e shuffle.*

## O que faz

Mostra o que está tocando no Spotify ou Apple Music — capa do álbum e um
visualizador de áudio animado no notch fechado; passar o mouse expande com
controles de play/pause, próxima/anterior, barra de progresso e shuffle. O
visualizador usa um tap de áudio real via CoreAudio (FFT em 5 bandas) no
processo do player, como o Dynamic Island do iPhone — as barras dançam com a
música de verdade, tingidas pela cor dominante da capa. Sem áudio real
disponível (ou sem a permissão concedida), cai num visualizador sintético.
Música pausada some do notch; passar o mouse "espia" antes de comprometer a
abertura.

## Como usar

- Hover no notch fechado expande; tirar o mouse fecha.
- Dois dedos pra baixo abre, pra cima fecha, gesto horizontal pula faixa.
- Funciona com qualquer app que apareça no Control Center (Now Playing
  universal via `mediaremote-adapter`) — não é exclusivo de Spotify/Apple Music.
- Em monitores externos (sem notch físico), a mesma UI aparece numa ilha
  simulada no topo da tela.

## Permissões

- **Gravação de Áudio do Sistema** — *"Knobler lê o áudio do player para
  animar o visualizador no notch, como no iPhone."* Sem ela, o visualizador
  usa animação sintética em vez do áudio real.
- **Automação** (Spotify/Music) — necessária pros comandos de play/pause/skip.
```
