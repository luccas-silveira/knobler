# Plano — site do Knobler

Objetivo: refazer o site em `site/` dentro do repo do app, com versão, download, novidades e docs lidos do repo a cada build, e publicação automática no release.

Spec: `docs/vesta/specs/2026-09-25-site-design.md`
Teste: `node --test site/tests/*.test.mjs`
Pastas de tela: `site/src`
Mockup: `docs/vesta/mockups/2026-09-25-site/index.html`

Referências do site antigo (repo `~/Desktop/Projetos/knobler-site`, só leitura): `src/components/NotchShape.astro`, `src/components/CodeBlock.astro`, `src/data/features.ts:17-197` (rascunho de textos), `src/assets/screenshots/` (22 PNGs escuros), `DESIGN.md` (tokens), `scripts/dark-screenshots/` (gera PNGs escuros a partir do código do app).

- **Como fazer:** copiar `package.json`, `astro.config.mjs` e `tsconfig.json` de `~/Desktop/Projetos/knobler-site` (Astro `^7.1.3`, `engines.node >=22.12.0`, `site: "https://knobler.appzoi.com.br"`). Rodar `npm install` em `site/` e commitar o `package-lock.json`. Testes em `node:test` + `node:assert/strict`, ESM (`.mjs`).

## Etapa 1 — Leitura do CHANGELOG e das novidades

- **Tela:** não.
- **Arquivos:** criar `site/src/lib/changelog.mjs`, `site/tests/changelog.test.mjs`.
- **O que prova:**
  - `parseChangelog(texto)` ignora `## [Unreleased]` e devolve as versões em ordem, cada uma com `version`, `date` e seções (`Added`, `Fixed`, `Changed`, `Removed`, `Documentation`) com seus itens; item que quebra em várias linhas vira um item só.
  - Tolera linha em branco ou não entre `### X` e o primeiro item.
  - `currentVersion(texto)` devolve a primeira versão numerada; texto sem nenhuma versão numerada lança erro com mensagem clara.
  - `downloadUrl("0.35.2")` = `https://github.com/luccas-silveira/knobler/releases/download/v0.35.2/Knobler-0.35.2.zip`.
  - `novidadesHtml(version, dir)` devolve o conteúdo de `Knobler/Novidades/<version>.html` quando existe e `null` quando não; caminhos `midia/...` dentro dele são reescritos para `/novidades/midia/...`.
  - Um teste roda contra o `CHANGELOG.md` real do repo e confere que a versão atual casa com `^\d+\.\d+\.\d+$`.
- **Como fazer:** formato real em `CHANGELOG.md:7-20` (cabeçalho `## [X.Y.Z] - YYYY-MM-DD`). Fragmentos de novidades: `Knobler/Novidades/0.35.0.html` (sequência de `<section class="novidade">`). Funções puras, sem dependência; caminhos resolvidos a partir de `new URL("../../..", import.meta.url)` (raiz do repo).

## Etapa 2 — Leitura dos docs técnicos com reescrita de links

- **Tela:** não.
- **Arquivos:** criar `site/src/lib/docs.mjs`, `site/src/data/recursos-slugs.mjs` (mapa `arquivo.md` → slug de recurso), `site/tests/docs.test.mjs`.
- **O que prova:**
  - `DOCS` lista exatamente `local-api`, `webhooks`, `plugins`, `troubleshooting`; um arquivo da lista ausente lança erro.
  - Link para um doc da lista vira `/docs/<slug>` (com âncora preservada).
  - Link para doc com página de recurso vira `/recursos/<slug>` (ex.: `notifications.md` → `/recursos/notificacoes`, `texto-da-tela.md` → `/recursos/texto-da-tela`).
  - Link para qualquer outro arquivo do repo vira `https://github.com/luccas-silveira/knobler/blob/master/<caminho>` (ex.: `relay-operacao.md`, `development.md#instalação-local-do-build`).
  - Links que quebram linha entre `]` e `(` são reescritos igual.
  - URLs absolutas (`http…`) ficam intactas.
  - `images/x.png` vira `/docs/images/x.png` e aparece na lista de imagens a copiar.
- **Como fazer:** links externos à lista conhecidos: `docs/local-api.md:224,235,264`, `docs/webhooks.md:110`, `docs/plugins.md:27`, `docs/troubleshooting.md:243,305`. Reescrever no Markdown antes de renderizar (regex sobre `](...)`, com flag multilinha). O mapa de recursos usa os slugs da etapa 5.

## Etapa 9 — Capturas que faltam (mexe na máquina do usuário)

- **Tela:** sim — só troca imagens.
- **Arquivos:** novos PNGs em `site/src/assets/screenshots/` (conta-gotas, espelho, instalar-finder, instalar-alerta, instalar-privacidade, instalar-permissoes); tirar `imagemPendente` de `recursos.mjs` e `instalar.astro`.
- **O que prova:** o build falha se restar qualquer `imagemPendente` (teste em `site/tests/recursos.test.mjs` e `instalar.test.mjs` passa a exigir zero).
- **Como fazer:** **pedir ao usuário antes de cada captura.** Receita de captura em `.claude/skills/snapshot-ui/SKILL.md` e memória do projeto (`screencapture -R` com bounds de `CGWindowListCopyWindowInfo`, `sips -z` para 1x). Alerta do Gatekeeper: baixar o zip da release pelo navegador para uma pasta temporária, abrir, capturar o alerta e o painel de Privacidade e Segurança, e apagar a cópia. Não tocar no Knobler instalado em `/Applications`.

## Etapa 10 — Gate de build na CI

- **Tela:** não.

## Etapa 11 — Deploy e ligação com o release

- **Tela:** não.
- **Arquivos:** criar `site/deploy.sh`; mudar `tools/release.sh` (depois do bloco `gh release create`, `tools/release.sh:236-241`); mudar `docs/development.md` (seção "Site"); mudar `CHANGELOG.md` (`## [Unreleased]`, `### Changed`).
