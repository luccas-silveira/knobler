## Achados por prioridade

1. **Alta — token revogado volta após reiniciar o relay.** `relay/src/db.js:85` interpreta a ausência do hash antigo nos perfis como necessidade de migração. A rotação `/profiles/:id/rotate` só atualiza o perfil, deixando o hash antigo em `devices`. Reabrir o banco recria um perfil Padrão que aceita o token revogado. Apagar esse perfil também não persiste após reiniciar. Reproduzido com banco temporário e servidor HTTP local. Corrigir a migração para executá-la uma única vez e preservar a revogação nas operações subsequentes.

2. **Alta — apagar perfil sem rede perde a cópia local do token.** `Knobler/WebhookClient.swift:384` apaga o token do Keychain mesmo se o DELETE falhar. `authed`, na linha 334, também ignora o status HTTP. O perfil pode continuar ativo no relay e perder o botão de copiar link no app. Confirmado pelo fluxo do código; não exercitado contra o Keychain real. Validar status e só apagar o segredo após confirmação de sucesso.

3. **Média — falha ao salvar conversão destrói o resultado temporário.** `Knobler/ShelfPreview.swift:111` apenas registra o erro; linhas 115–116 descartam todos os resultados, inclusive os que não foram movidos. `ShelfStore.confirmPreview` fecha o preview mesmo sem nenhum arquivo salvo. Reproduzido renomeando a pasta de origem entre converter e salvar: zero arquivos salvos, temporário removido, `failed == false`. O original permanece intacto. Preservar resultados não salvos e permitir tentar novamente.

4. **Média — mapping aceito pela API quebra o recebimento do webhook.** `relay/src/server.js:160` valida apenas se o mapping é JSON. A string JSON `null` recebe HTTP 200 no PUT, mas o webhook seguinte retorna 500 ao acessar `m.title`. Reproduzido via HTTP local. Validar objeto e tipos dos campos antes de persistir.

5. **Baixa — reimportar arquivo fecha a pilha aberta prematuramente.** `Knobler/ShelfOrdem.swift:130` escolhe a primeira entrada com qualquer interseção com a pilha antiga. Reimportar A de [A,B,C] cria [A] antes de [B,C]; a reconciliação encontra [A] e fecha a grade. Reproduzido com o modelo real. A reconciliação precisa considerar a pilha remanescente, inclusive quando a nova entrada contém vários arquivos.

## Otimização concreta

`Knobler/WebhookClient.swift:350`: listar N perfis dispara 1 + N requests sequenciais para obter `lastPayloadAt`. O relay já possui o campo. Devolvê-lo em `GET /profiles` elimina as consultas individuais: 50 perfis passam de 51 requests para 1. Não foi medido tempo de resposta de produção; o ganho demonstrável é a redução do número de requests.

## VIS-01 — defeito visual da captura (em investigação)

Continuação em 09/09/2026: [medições e coletor de ocorrência ativa](diagnostico-visual.md).

Sintoma relatado: o knob às vezes permanece aberto com uma grande área vazia acima da faixa de ícones. A captura pessoal não foi incorporada ao repositório. Não foi estabelecido se este sintoma tem a mesma causa do corte investigado anteriormente.

No momento da revisão, o processo em execução era `/Applications/Knobler.app`, versão 0.27.0, e contém `VigiaDoCorte`. Não foi encontrado o arquivo esperado `~/Library/Application Support/Knobler/corte-do-knob.jsonl`. Na consulta de status posterior, os três knobs estavam fechados.

O detector em `Knobler/CorteDoKnob.swift` mede geometria de layout, não os pixels finais da tela. O [mapa anterior](wayfinder/map-corte-do-knob.md) já registra esse limite. A ausência de registro é compatível com esse ponto cego, mas não demonstra a causa da captura. Não foi reproduzido o defeito intermitente nesta revisão. Para distinguir layout de composição, é necessário comparar uma captura da tela no instante do defeito com o estado/geometria do mesmo instante. Os testes de modelo e snapshots offscreen não comprovam correção desse sintoma.
